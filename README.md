# 抖音 / 快手收藏自动下载 · v1.7.3

**你只管正常刷视频、点「收藏」，视频会自动以最高画质、无水印保存到本地，全程不弹窗、不切页面。**

![版本](https://img.shields.io/badge/version-1.7.3-fe2c55) ![Python](https://img.shields.io/badge/python-3.10%2B-25f4ee) ![平台](https://img.shields.io/badge/platform-Windows-blue)

---

## 它是什么样的

- 接管一个你自己登录过的 Chrome，**你平时怎么刷就怎么刷**
- **抖音和快手都支持**：同一个浏览器里刷哪个站、点哪个站的收藏，就下哪个
- 点一下「收藏」→ 后台静默下载 → 面板上实时出现进度条
- 打开「自动下载推荐页视频」+「自动翻页」，连收藏都不用点，刷到哪下到哪
- 自动挑**分辨率最高、码率最高**的那一路原片，过滤 `playwm` 等带水印地址
- 不伪造请求、不碰签名算法，所以没有签名失效和风控问题

# 快速开始

## 1. 环境要求

- Windows 10 / 11
- Python 3.10 及以上
- 本机装有 **Google Chrome**
- 首次需要联网安装两个依赖

## 2. 安装依赖

```bash
pip install -r requirements.txt
```

## 3. 启动

双击 `启动收藏下载.bat`，或者命令行：

```bash
python douyin_dl.py
```

首次运行会拉起一个 Chrome 窗口，**扫码登录抖音**（登录态存在 `.chrome_profile/`，以后不用再登）。
登录后照常刷视频、点收藏即可，下载会自己跑。

面板会自动打开：<http://127.0.0.1:8899/>

# 常用命令

```bash
python douyin_dl.py                  # 正常监听收藏（默认带面板）
python douyin_dl.py --download-all   # 启动时把现有收藏全部补下回来
python douyin_dl.py --url <分享链接>  # 只下单个视频，不启动监听
python douyin_dl.py --check          # 只看登录状态
python douyin_dl.py --output D:\视频  # 指定下载目录
python douyin_dl.py --no-ui          # 不要面板
python douyin_dl.py --ui-port 9000   # 换面板端口
```

后台守护（崩了自动拉起，推荐日常使用）：

```bash
python douyin_dl/daemon.py
```

双击 `启动收藏下载.bat` 走的就是这条路：守护进程 + 主程序都在后台，面板自动弹出。
想彻底停掉：用任务管理器结束 `douyin_dl.py` / `daemon.py` 对应的 `pythonw.exe` 进程；或按命令行精确筛出本工具的进程再结束（PowerShell）：

```powershell
Get-CimInstance Win32_Process -Filter "name='pythonw.exe'" |
  Where-Object { $_.CommandLine -like '*douyin_dl.py*' -or $_.CommandLine -like '*daemon.py*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

**别图省事按进程名 `pythonw.exe` 一刀切全杀** —— 那种写法会把系统里**所有** `pythonw.exe` 进程一起结束，包括其它软件、其它 Python 脚本起的后台进程，不只本工具。上面按命令行筛一遍，才只动本工具自己的进程。
连续 5 次启动即秒退时守护会放弃，避免无限重启。

# 画质

- 默认「最高画质」：在所有候选地址里按 **分辨率面积 → 码率 → 体积** 排序取第一
- 面板里可以设上限（1080P / 720P / 480P），适合省流量
- 下载支持 **Range 断点续传**（`.part` 临时文件），中断后重下会接着写
- 下完用 MP4 魔数（`ftyp`）或 ffprobe 校验，损坏的文件不会留下
- 图文作品按 `01.jpg / 02.jpg …` 存进同名文件夹

# 工作原理

```
你点「收藏」
   ↓
页面钩子(注入的 JS) 捕获 /aweme/v1/web/aweme/collect/ 请求
   ↓  请求体里 action=1 才是收藏，action=0 是取消
通过 Playwright expose_binding 直接回调 Python（零网络请求，绕开 CSP）
   ↓
无头 Chrome 带同一份 Cookie 打开详情页，抓一份「此刻有效」的播放地址
   ↓
按分辨率/码率选最优候选 → requests 多线程外下载 → 校验 → 落盘 → 通知面板
```

几个关键设计：

- **只认接口里的 `action=1`**，不依赖「点击坐标对得上号」这种脆弱判断（实测过：连点两个视频时点击记录会错位）
- **收藏列表只用来记录基线，永不触发下载** —— 列表第一页会自己轮换，拿它 diff 必然把历史收藏反复重下
- **每次下载都重新抓详情，不复用缓存** —— 播放地址签名很快过期，用旧地址会整片 403
- **候选地址全部失败时会逐个换**，不会因为第一条 403 就放弃
- 补全详情走**无头浏览器**，所以你眼前不会跳任何窗口或标签页

# 常见问题

**点了收藏没反应？**
看 `douyin_dl.log` 最后几行：

| 日志 | 含义 |
| --- | --- |
| 没有任何新行 | 钩子没认出按钮，或你点的不是这个 Chrome 窗口 |
| `检测到收藏点击` 但后面没有 `新收藏` | 请求没发出去 |
| `取消收藏 xxx (不下载)` | 这个视频本来就是已收藏的，点一下是取消 |
| `抓取最新视频信息` 后卡住或 `拿不到` | 详情接口没返回，会自动重试 |
| `所有候选地址都下载失败` | 该视频地址全部被拒（少见），日志里有完整 URL |

**提示「已经有一个下载进程在运行」**：程序是单实例的，会把已有窗口切到前台，直接刷就行。确实想重开就先关掉原来的窗口。

**双击后没有抖音窗口**：Chrome 被关掉后旧进程会自己退出并释放锁，重新双击即可。

**面板显示的还是旧样式**：浏览器缓存了旧页面，按 `Ctrl + F5` 强制刷新一次。

# 注意

- 监听期间**别关那个 Chrome 窗口**（可以最小化）
- 启动时会先记下你现有的收藏，**只下载这之后新收藏的视频**；想把历史收藏也补回来用 `--download-all`
- 取消收藏不会触发下载
- 仅供个人备份自己收藏的内容使用

# 更新记录

## v1.7.3

**主题：修「快手时好时坏，退出重进就又下不了」—— CDP 补漏注入孤儿半死页。**

- **根因**：快手 `new-reco` 页如果在程序启动**之后**才打开，Playwright 对它的
  attach 从一开始就失败，它既**不进 `ctx.pages`、也不触发 `ctx.on("page")`**，
  主程序完全"看不见"它。而 `_hook_all_pages` 只遍历 Playwright 可见的 `ctx.pages`，
  所以这个页面永远装不上钩子、收藏事件全丢。之前"能下"的场景是快手页在启动时
  已存在（attach 成功），之后才变半死页，能被 `_install_hook` 看到走 raw 通道。
- **补漏**：`_hook_all_pages` 现在除了遍历 `ctx.pages`，还直接问 CDP `/json/list`
  拿全部 page target，对 Playwright 漏掉的站点页走**纯 CDP 注入 + raw binding 通道**
  （新增 `_cdp_probe(tid)` 按 targetId 探活、`_ensure_raw_binding_by_tid(tid)` 按 tid
  建通道），不再依赖 page 对象。
- **回归测试**：新增 1 例（孤儿半死页经 CDP 补漏注入），全量 239 例通过。

## v1.7.2

**主题：修「快手收藏点不动」—— 半死页改用独立 CDP 通道回传事件。**

- **根因**：快手 `new-reco` 页在 Playwright 驱动侧是「半死页」—— CDP 层还活着、
  渲染进程也活着，但 Playwright 对这个页面的 attach 断了：`page.url` 读成空串，
  `page.evaluate` 永久挂起，更关键的是 `expose_binding` 注入的 `__dyReport` 回传
  通道断裂，所以收藏事件**根本传不回来**（日志里连「检测到收藏点击」都没有）
- **raw CDP 通道**：新增独立 websocket 长连接 + `Runtime.addBinding("__dyReportRaw")`，
  后台线程收 `Runtime.bindingCalled` 事件直接入队，完全不经过 Playwright attach；
  HOOK_JS 的 `send()` 优先走这条通道，走不通才退回旧的 `expose_binding`
- **半死页识别**：`page.url` 为空时用 CDP `Target.getTargetInfo` 再问一次真实 URL，
  认出来是站点页就不再误判成「非站点页」跳过；装钩子时对半死页改走 CDP `Runtime.evaluate`
  注入（带硬超时），绝不碰会挂起的 `page.evaluate`
- **回归测试**：新增 3 例（半死页 URL 兜底 / 半死页走 raw 通道不 evaluate / HOOK_JS
  优先 raw 通道），全量 237 例通过

## v1.7.1

**主题：修「切到快手后抖音也下不了」的卡死 —— 坏页面看门狗。**

- **根因**：Playwright 的 `Page.evaluate()` 没有超时参数，遇到渲染进程挂掉的坏页面
  （比如快手 `new-reco` 页在驱动侧变成空 URL）会**永久阻塞**，把主循环每 6 秒一次的
  钩子巡检钉死，导致抖音、快手两个站点的收藏事件全部收不到、日志一片空白
- **坏页面看门狗**：给每个页面加 CDP 级硬超时探活（4 秒，不碰页面渲染进程），
  探不活的页面拉黑 120 秒跳过，绝不再对它 `evaluate`；派发事件时也跳过坏页、
  没有健康站点页就退回浏览器级 CDP，主循环从此不再被单个坏页拖死
- **守护进程修复**：运行期间又双击「启动收藏下载.bat」会提示「已经有一个下载进程
  在运行」，这件事不再被守护进程当成「秒退」计数 —— 之前连点 5 次会触发
  `连续 5 次秒退` 上限，导致守护不再兜底
- **回归测试**：新增 6 例（坏页面跳过 / 探活失败拉黑 / 成功解禁 / 拉黑期内跳过 /
  pump 挑健康站点页 / 无站点页退回浏览器 CDP），全量 234 例通过

## v1.7.0

**主题：加入快手 —— 刷快手时点收藏，一样自动下载最高画质无水印原片。**

- **双站点**：同一个浏览器、同一个面板里，抖音和快手可以一起刷，收藏哪个下哪个；
  登录墙、页面保活、自动翻页都认两个站点，不再因为只开快手就被反复弹去抖音
- **快手走「搭便车 + 直链缓存」**：实测快手 CDN 的 mp4 地址不带签名、不需要 Cookie、
  几十分钟前抓到的仍能裸请求下完（23MB 实测通过校验）。所以收藏时直接用页面自己
  发的 feed 响应里那份码率表提交下载，零延迟，也完全绕开快手详情页那套
  「浏览器版本过低」风控
- **最高画质照旧**：遍历 `manifest` + `manifestH265` 的所有 `adaptationSet → representation`
  档位（含 `backupUrl`），按分辨率面积 → 平均码率 → 文件体积挑最大的一路
- **兜底与恢复**：从分享链接直接进详情页、feed 缓存里没有时，才尝试读详情页的
  `window.__APOLLO_STATE__`（自动解引用 Apollo 的 `type:id` / `type:json` 引用）；
  被风控挡了会明确提示「往下滑一下让列表重新加载再收藏一次即可」，不会静默失败
- **面板兼容**：记录 id 支持快手那种字母数字混排的 photoId，同时保留路径穿越防护
- **回归测试**：新增 27 例（含一次真浏览器注入钩子，把「快手点击事件的
  `photoId` 永远为空」这个隐藏 bug 当场抓出来，以及一条完整的快手落盘链路），
  全量 228 例通过

## v1.6

**主题：更耐用 —— 抖音/浏览器/环境怎么变，都尽量还能用；顺手修掉一批大小 bug。**

- **抖音接口字段再变也不怕**：视频 id 认 `aweme_id`/`awemeId`/`itemId`/`object_id` 等别名，
  收藏动作认 `1`/`0`/`true`/`collect`/`favorite`/`cancel` 等形态， aweme 被多包一层、
  或整段是 JSON 字符串也照样挖得出来；不再写死某个字段名/长度，接口小改不至于整条链失效
- **抓取钩子更稳**：等请求体+响应体都到齐再上报（修异步竞态导致的偶发漏收藏），
  响应超过 32MB 直接丢弃而不是截成无效 JSON，Chrome 找不到时会自动找 Edge、翻注册表和 PATH
- **登录判定更准**：只认真正登录才会有的 Cookie（`sessionid`/`sid_guard`/`uid_tt` 等），
  游客态的 `ttwid`/`msToken` 不再被误当登录，避免"明明没登录却一直不提示、全是 403"
- **坏数据不崩**：状态文件/设置文件/网络响应被写坏、被手工改坏、或半截断电，
  一律按类型归一化兜底，不会让面板白屏、下载线程崩掉或统计错乱；设置改原子写，不留半截坏文件
- **改目录立即生效**：面板里切换下载目录，正在跑的下载线程马上跟过去，不用重启
- **重试不卡面板**：点重试改成后台处理，面板不再冻住几十秒，也不会因为连点重复抓
- **长跑更省心**：待办/已见集合设上限防内存膨胀；面板断线能自动补服务；
  浏览器/登录失败给出明确退出码，守护进程不再把故障当"正常退出"反复重启
- **失败出口更明确**：`--check` 提前到起面板/抢锁之前，检查登录不会留下残留锁文件
- 回归测试从 43 个扩到 119 个，新增的畸形输入用例还揪出一个"列表被当成视频 id"的隐藏 bug

## v1.4

**新功能：自动下载推荐页视频（设置里开关，默认关）**

- 面板右上「设置」→「自动下载推荐页视频」→ 开。开着刷推荐页时，加载到的视频
  （推荐信息流 + 相关推荐）会自动进下载队列，不用一个个点收藏
- 「关」时和以前完全一样：只下载你收藏的
- 三个去重防线：同一会话不重复提交；已收藏的不重复下；已下载过的由下载器兜底跳过
- 开关即时生效，不用重启

## v1.3

这一版没加新功能，专门做体检：把整个项目逐行过了一遍，修掉 16 处会踩到的问题。
其中好几处是「平时看不出来，真遇上就束手无策」的那种。

**修好的坑**

- **返回顶部按钮点了没反应** —— 按钮里写的是 `scrollTo(...)`，在按钮自己的作用域里被解析成
  元素自己的滚动方法，而不是页面滚动。改成 `window.scrollTo` 并把逻辑收进 `goTop()`，
  另外加了 `T` 快捷键
- **校验失败的文件永远修不好** —— 下完之后发现不是有效视频，文件留在原地，
  再点重试就命中「已存在，跳过」，只能手动去文件夹里删。现在校验失败直接删掉
- **断点续传遇到 416 会卡死** —— 服务器说「你这段已经下完了」，老代码却当成失败，
  留下一个下载不掉的残片，这个视频从此再也下不下来。现在直接用已有的残片收尾
- **半截文件被当成成品** —— 网络中断时会得到一个大小不对的「完成」文件。加了长度校验，
  长度不够就继续下，不写成品
- **画质排序是反的** —— 「按画质」用的字符串比较，`720x1280` 排在了 `1080x1920` 前面。
  改成按分辨率面积比
- **图集作品永远挂在「排队中」** —— 图文作品下载完没发完成通知，面板上一直以为它还在排队
- **下载失败却一声不吭** —— 视频被删/私密/需要登录时抓不到详情，以前只是后台默默跳过，
  现在会带着原因出现在面板的失败列表里，点一下就重试
- **删除记录可能被「复活」** —— 面板直接改状态文件，和下载线程抢着写，删掉的记录会被写回来。
  改成由后台持锁统一删
- **面板断线时毫无提示** —— 所有按钮的请求都裸着发，后台一断就静默失败。现在统一走一个
  带容错的请求函数，断了会弹提示
- **未知大小时进度条永远是 0%** —— 服务器不给长度时看起来像卡死。现在直接显示「已下载 3.8 MB」
- **卡片墙每次推送都整体重建** —— 150 多张卡片每秒重建一遍，鼠标悬停会闪、图片会重新加载。
  加了内容指纹，没变化就不动 DOM
- **设置文件每秒被读 3 次** —— 合成一份状态要读三遍 `.settings.json`，现在只读一遍
- **控制台一直刷 favicon 404** —— 补了 204 响应
- **面板接口可以被路径穿越** —— `?id=../../etc/passwd` 这类 id 现在会被挡掉
- **卡片 onclick 里的 id 没转义** —— 加了白名单过滤
- **日志文件无限增长** —— 超过 5 MB 自动轮转一份

**顺手的改进**

- 打开设置抽屉立刻就能看到日志，不用等 3 秒轮询
- 重试成功后，失败列表里那条会自动消失

**测试**

- 新增 `tests/test_panel.py`：在临时目录造数据、起一个独立面板，用无头浏览器把搜索、
  筛选、排序、设置、快捷键、右键菜单、排队/进度/失败、重试、删除、接口健壮性等
  40 多项逐条跑一遍，不碰真实下载目录

## v1.1

在 v1.0 基础上把「能跑」做成了「好用、不添乱」：

- **守护模式**：主进程崩了自动拉起；连续 5 次秒退则放弃，不会无限重启
- **失败列表 + 一键重试**：下载失败的会留在面板上，点重试重新抓地址再下一次
- **卡片右键菜单**：打开视频 / 打开所在文件夹 / 复制链接 / 删除记录和文件
- **近 14 天柱状图**：每天下载条数一目了然
- **按作者分文件夹**（默认关）：开了以后存进 `downloads/作者名/`
- **退出抖音后行为可控**：设置里可选「关掉抖音监听自动结束」或「自动重新打开」
- **面板单实例**：重复启动不会开出一堆面板标签
- **界面美化**：深空灰蓝配色、竖屏封面墙、操作按钮常显、图表可折叠、键盘快捷键与回顶按钮
- **点「打开」直接播放**：不再只是跳到文件夹；播放器窗口还会自动弹到最前面，
  不用再去任务栏点一下
- **日志整合**：顶栏「查看日志」一个入口，抽屉里直接看最近 200 行
- 修了一批健壮性问题：设置文件损坏、日志参数非法、单实例锁、无头页面失效自愈、
  取消收藏时撤销待下载、前端静默白屏等
