# 抖音 / 快手 / B站收藏自动下载 · v2.5

**你只管正常刷视频、点「收藏」，视频会自动以最高画质、无水印保存到本地，全程不弹窗、不切页面。**

![版本](https://img.shields.io/badge/version-2.5.0-fe2c55) ![Python](https://img.shields.io/badge/python-3.10%2B-25f4ee) ![平台](https://img.shields.io/badge/platform-Windows-blue)

---

## 它是什么样的

- 接管一个你自己登录过的 Chrome，**你平时怎么刷就怎么刷**
- **抖音、快手、B站三个平台都支持**：同一个浏览器里刷哪个站、点哪个站的收藏，就下哪个
- **面板上一键打开任意平台**：点「打开」里的抖音/快手/B站按钮，直接在已经登录的浏览器里开好对应页面
- 点一下「收藏」→ 后台静默下载 → 面板上实时出现进度条
- 打开「自动下载推荐页视频」+「自动翻页」，连收藏都不用点，刷到哪下到哪
- 自动挑**分辨率最高、码率最高**的那一路原片，过滤 `playwm` 等带水印地址
- B站走 DASH 音视频分离流，下载后自动用 ffmpeg 无损合并成一个 mp4
- 不伪造请求、不碰签名算法，所以没有签名失效和风控问题

# 快速开始

## 1. 环境要求

- Windows 10 / 11
- Python 3.10 及以上
- 本机装有 **Google Chrome**
- 首次需要联网安装两个依赖

## 2. 安装依赖

```bash
pip install -r requirements.txt
```

## 3. 启动

双击 `启动收藏下载.bat`，或者命令行：

```bash
python douyin_dl.py
```

首次运行会拉起一个 Chrome 窗口，**扫码登录抖音**（登录态存在 `.chrome_profile/`，以后不用再登）。
登录后照常刷视频、点收藏即可，下载会自己跑。

面板会自动打开：<http://127.0.0.1:8899/>

# 常用命令

```bash
python douyin_dl.py                  # 正常监听收藏（默认带面板）
python douyin_dl.py --download-all   # 启动时把现有收藏全部补下回来
python douyin_dl.py --url <分享链接>  # 只下单个视频，不启动监听
python douyin_dl.py --check          # 只看登录状态
python douyin_dl.py --output D:\视频  # 指定下载目录
python douyin_dl.py --no-ui          # 不要面板
python douyin_dl.py --ui-port 9000   # 换面板端口
```

后台守护（崩了自动拉起，推荐日常使用）：

```bash
python douyin_dl/daemon.py
```

双击 `启动收藏下载.bat` 走的就是这条路：守护进程 + 主程序都在后台，面板自动弹出。
想彻底停掉：用任务管理器结束 `douyin_dl.py` / `daemon.py` 对应的 `pythonw.exe` 进程；或按命令行精确筛出本工具的进程再结束（PowerShell）：

```powershell
Get-CimInstance Win32_Process -Filter "name='pythonw.exe'" |
  Where-Object { $_.CommandLine -like '*douyin_dl.py*' -or $_.CommandLine -like '*daemon.py*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

**别图省事按进程名 `pythonw.exe` 一刀切全杀** —— 那种写法会把系统里**所有** `pythonw.exe` 进程一起结束，包括其它软件、其它 Python 脚本起的后台进程，不只本工具。上面按命令行筛一遍，才只动本工具自己的进程。
连续 5 次启动即秒退时守护会放弃，避免无限重启。

# 画质

- 默认「最高画质」：在所有候选地址里按 **分辨率面积 → 码率 → 体积** 排序取第一
- 面板里可以设上限（1080P / 720P / 480P），适合省流量
- 下载支持 **Range 断点续传**（`.part` 临时文件），中断后重下会接着写
- 下完用 MP4 魔数（`ftyp`）或 ffprobe 校验，损坏的文件不会留下
- 图文作品按 `01.jpg / 02.jpg …` 存进同名文件夹

# 工作原理

```
你点「收藏」
   ↓
页面钩子(注入的 JS) 捕获 /aweme/v1/web/aweme/collect/ 请求
   ↓  请求体里 action=1 才是收藏，action=0 是取消
通过 Playwright expose_binding 直接回调 Python（零网络请求，绕开 CSP）
   ↓
无头 Chrome 带同一份 Cookie 打开详情页，抓一份「此刻有效」的播放地址
   ↓
按分辨率/码率选最优候选 → requests 多线程外下载 → 校验 → 落盘 → 通知面板
```

几个关键设计：

- **只认接口里的 `action=1`**，不依赖「点击坐标对得上号」这种脆弱判断（实测过：连点两个视频时点击记录会错位）
- **收藏列表只用来记录基线，永不触发下载** —— 列表第一页会自己轮换，拿它 diff 必然把历史收藏反复重下
- **每次下载都重新抓详情，不复用缓存** —— 播放地址签名很快过期，用旧地址会整片 403
- **候选地址全部失败时会逐个换**，不会因为第一条 403 就放弃
- 补全详情走**无头浏览器**，所以你眼前不会跳任何窗口或标签页

# 常见问题

**点了收藏没反应？**
看 `douyin_dl.log` 最后几行：

| 日志 | 含义 |
| --- | --- |
| 没有任何新行 | 钩子没认出按钮，或你点的不是这个 Chrome 窗口 |
| `检测到收藏点击` 但后面没有 `新收藏` | 请求没发出去 |
| `取消收藏 xxx (不下载)` | 这个视频本来就是已收藏的，点一下是取消 |
| `抓取最新视频信息` 后卡住或 `拿不到` | 详情接口没返回，会自动重试 |
| `所有候选地址都下载失败` | 该视频地址全部被拒（少见），日志里有完整 URL |

**提示「已经有一个下载进程在运行」**：程序是单实例的，会把已有窗口切到前台，直接刷就行。确实想重开就先关掉原来的窗口。

**双击后没有抖音窗口**：Chrome 被关掉后旧进程会自己退出并释放锁，重新双击即可。

**面板显示的还是旧样式**：浏览器缓存了旧页面，按 `Ctrl + F5` 强制刷新一次。

# 注意

- 监听期间**别关那个 Chrome 窗口**（可以最小化）
- 启动时会先记下你现有的收藏，**只下载这之后新收藏的视频**；想把历史收藏也补回来用 `--download-all`
- 取消收藏不会触发下载
- 仅供个人备份自己收藏的内容使用

## v2.5

**主题：离线也能刷 —— 双击 `离线刷视频.bat`，不联网、不碰浏览器。**

- **问题**：以前离线播放器寄生在下载主程序里，而主程序启动链路必然

- **做法**：`douyin_dl.py` 新增 `--offline`（别名 `--player-only`）—— 只做

## v2.2.2

**主题：面板加载慢 / 卡顿 —— 历史记录重扫从 944ms 降到 51ms。**

- **根因 1（最大头）**：`_recent()` 给每条记录都算一次 `workspace.resolve()`。
  Windows 上一次 resolve 要走 `nt._getfinalpathname` 系统调用，443 条记录就是
  886 次，实测吃掉 694ms。改成**纯字符串判定**路径穿越（出现 `..` 段才拒），
  不碰文件系统。攻击样本全部复测，防护一点没松。
- **根因 2**：每次 `finish()` / `fail()` / `delete()` 都把历史缓存置 `None`，
  于是**每下完一个视频就全量重扫 443 条**。改成"元信息签名"缓存：只看
  `.state.json` 的 `(mtime, size)` 和 `_meta` 目录的 `(mtime, 文件数)`，
  签名没变就直接复用缓存。
- **根因 3**：每条记录要对 `_meta` 目录做一次 `exists()` —— 443 条 × 2 个目录
  = 886 次 stat，占重扫耗时的 70%。改成先用 `os.scandir` 把目录项读成
  名字索引，查表代替逐条 stat。顺手把 `exists()+stat()+is_dir()` 三次调用
  合并成一次（`stat` 的 `st_mode` 里本来就有类型）。
- **根因 4**：同一次重扫里，443 条记录落在同一个下载目录，却逐条去 `stat`
  这个目录查 mtime。改成**一帧只验一次**。
- **实测**：`_recent()` 冷启动 **944ms → 51ms（快 18.5 倍）**，命中缓存
  **0.35ms**，`snapshot()` **1.9ms → 1.0ms**。
- **回归测试**：新增 `tests/test_perf_ui.py` 33 例 —— 9 种路径穿越攻击样本、
  8 种垃圾输入、5 种正常路径、缓存失效的 4 个场景（改文件 / 新 meta /
  finish 不清缓存 / 目录被 stat 的次数上限）、已删文件与新文件的识别。
  全量 **329 例通过**。

## v2.2.1

**主题：B站下载完会闪一下命令行黑框 —— 子进程都没隐藏窗口。**

- **根因**：主程序是用 `pythonw.exe` 启动的（没有控制台）。Windows 的规则是：
  **没有控制台的进程再 spawn 子进程，系统会主动给子进程新建一个控制台窗口**。
  B站下完要调 `ffmpeg` 合并音视频，于是黑框一闪而过。同样会闪的还有 `ffprobe`
  校验、`yt-dlp` 解析、`powershell` 探测进程。
- **修复**：在 `core.py` 加了 `run_hidden()` / `popen_hidden()` 两个 helper，统一
  带上 `CREATE_NO_WINDOW`；把 `bili.merge_av`（ffmpeg）、`core.verify_video`
  （ffprobe）、`douyin_dl.main`（yt-dlp、powershell）、`watcher.start_chrome`
  （Chrome）、`ui` 的「在文件夹中显示」（explorer）、`daemon` 拉起子进程全部改走它。

## v2.2

**主题：大文件下载太慢 —— 分段并发，把一条连接吃不满的带宽抢回来。**

- **为什么慢**：CDN 通常限的是**单条 TCP 连接**的速率，不是账号速率。实测同一个
  B站 448.7MB 4K 轨，单连接只有 1.96 MB/s，而同时开 8 条连接能到 13.37 MB/s
  —— 也就是说带宽一直闲着，只是程序只用了其中一条管子。
- **做法**：新增 `download_parallel`，先用 `Range: bytes=0-0` 探出文件总长，再把它
  切成 N 段、N 条连接并发拉、各自按偏移写进同一个文件；进度回调报的是**所有段
  已完成字节之和**，所以面板上还是真实进度。新增 `download_smart` 做分流：**只有
  大于 8MB 的文件才并发**（小文件建连开销比下载还大），并且任何一段彻底失败就
  整体退回原来的单连接断点续传，不会因为并发失败把整条视频废掉。
- **面板可调**：设置抽屉新增「下载连接数」，0~16 路（0/1 = 关掉并发走单连接），
  默认 8。**改了立即生效**，不用重启 —— 每次下载都会重新读设置。
- **修掉一个会下出错位文件的严重 bug**：探总长时原来 200/206 都当成"支持 Range"。
  如果服务端忽略 `Range` 直接回整个文件，每个分段都会从头开始写，拼出来的文件是
  错位的垃圾**却返回成功**。现在要求必须 `206 + Content-Range` 才算支持，每一段
  也校验状态码，不支持就明确退回单连接。
- **实测**：448.7MB 4K 轨 8 路并发 **32.09 MB/s**，偏移抽查 0 / 235MB / 470MB 三处
  sha256 与远端单独请求**逐字节一致**；真实 `Downloader.process` 跑 B站 4K 全链路
  （18 候选 → 448.7MB 视频轨 + 7MB 音频轨 → ffmpeg 合并 → 456MB / 34.6s，校验通过）。
  **提速幅度取决于 CDN 节点是否限单连接**，实测 1.2~6.8 倍不等，所以给了开关。
- **回归测试**：新增 `tests/test_parallel.py` 11 例（分段表无缝覆盖、拼装内容逐字节
  正确、真的开了多连接、进度单调、服务端不支持 Range 时必须失败、小文件走单连接、
  并发失败自动回退、连接数夹取），全量 **290 例通过**。

## v2.1.1

**主题：修「B站明明是大会员，下下来的却很糊」—— B站登录 Cookie 没有同步。**

## v1.3

这一版没加新功能，专门做体检：把整个项目逐行过了一遍，修掉 16 处会踩到的问题。
其中好几处是「平时看不出来，真遇上就束手无策」的那种。

**修好的坑**

- **返回顶部按钮点了没反应** —— 按钮里写的是 `scrollTo(...)`，在按钮自己的作用域里被解析成
  元素自己的滚动方法，而不是页面滚动。改成 `window.scrollTo` 并把逻辑收进 `goTop()`，
  另外加了 `T` 快捷键
- **校验失败的文件永远修不好** —— 下完之后发现不是有效视频，文件留在原地，
  再点重试就命中「已存在，跳过」，只能手动去文件夹里删。现在校验失败直接删掉
- **断点续传遇到 416 会卡死** —— 服务器说「你这段已经下完了」，老代码却当成失败，
  留下一个下载不掉的残片，这个视频从此再也下不下来。现在直接用已有的残片收尾
- **半截文件被当成成品** —— 网络中断时会得到一个大小不对的「完成」文件。加了长度校验，
  长度不够就继续下，不写成品
- **画质排序是反的** —— 「按画质」用的字符串比较，`720x1280` 排在了 `1080x1920` 前面。
  改成按分辨率面积比
- **图集作品永远挂在「排队中」** —— 图文作品下载完没发完成通知，面板上一直以为它还在排队
- **下载失败却一声不吭** —— 视频被删/私密/需要登录时抓不到详情，以前只是后台默默跳过，
  现在会带着原因出现在面板的失败列表里，点一下就重试
- **删除记录可能被「复活」** —— 面板直接改状态文件，和下载线程抢着写，删掉的记录会被写回来。
  改成由后台持锁统一删
- **面板断线时毫无提示** —— 所有按钮的请求都裸着发，后台一断就静默失败。现在统一走一个
  带容错的请求函数，断了会弹提示
- **未知大小时进度条永远是 0%** —— 服务器不给长度时看起来像卡死。现在直接显示「已下载 3.8 MB」
- **卡片墙每次推送都整体重建** —— 150 多张卡片每秒重建一遍，鼠标悬停会闪、图片会重新加载。
  加了内容指纹，没变化就不动 DOM
- **设置文件每秒被读 3 次** —— 合成一份状态要读三遍 `.settings.json`，现在只读一遍
- **控制台一直刷 favicon 404** —— 补了 204 响应
- **面板接口可以被路径穿越** —— `?id=../../etc/passwd` 这类 id 现在会被挡掉
- **卡片 onclick 里的 id 没转义** —— 加了白名单过滤
- **日志文件无限增长** —— 超过 5 MB 自动轮转一份

**顺手的改进**

- 打开设置抽屉立刻就能看到日志，不用等 3 秒轮询
- 重试成功后，失败列表里那条会自动消失

**测试**

- 新增 `tests/test_panel.py`：在临时目录造数据、起一个独立面板，用无头浏览器把搜索、
  筛选、排序、设置、快捷键、右键菜单、排队/进度/失败、重试、删除、接口健壮性等
  40 多项逐条跑一遍，不碰真实下载目录
