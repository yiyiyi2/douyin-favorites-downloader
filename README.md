# 抖音收藏自动下载 · v1.5

**你只管正常刷视频、点「收藏」，视频会自动以最高画质、无水印保存到本地，全程不弹窗、不切页面。**

![版本](https://img.shields.io/badge/version-1.5-fe2c55) ![Python](https://img.shields.io/badge/python-3.10%2B-25f4ee) ![平台](https://img.shields.io/badge/platform-Windows-blue)

---

## 它是什么样的

- 接管一个你自己登录过的 Chrome，**你平时怎么刷就怎么刷**
- 点一下「收藏」→ 后台静默下载 → 面板上实时出现进度条
- 打开「自动下载推荐页视频」+「自动翻页」，连收藏都不用点，刷到哪下到哪
- 自动挑**分辨率最高、码率最高**的那一路原片，过滤 `playwm` 等带水印地址
- 不伪造请求、不碰签名算法，所以没有签名失效和风控问题

# 快速开始

## 1. 环境要求

- Windows 10 / 11
- Python 3.10 及以上
- 本机装有 **Google Chrome**
- 首次需要联网安装两个依赖

## 2. 安装依赖

```bash
pip install -r requirements.txt
```

## 3. 启动

双击 `启动收藏下载.bat`，或者命令行：

```bash
python douyin_dl.py
```

首次运行会拉起一个 Chrome 窗口，**扫码登录抖音**（登录态存在 `.chrome_profile/`，以后不用再登）。
登录后照常刷视频、点收藏即可，下载会自己跑。

面板会自动打开：<http://127.0.0.1:8899/>

| 正在下载 | 实时进度条、速度、预计剩余秒数 |
| 排队中 | 已点收藏、正在抓取详情的视频 |
| 视频库 | 封面墙，支持搜索、按时间/大小/画质排序、只看今天/最近 20/图文，双击直接播放 |
| 失败列表 | 下载失败的会列出来，点「重试」重新抓地址再下一次 |
| 右键菜单 | 卡片上右键：打开视频 / 打开所在文件夹 / 复制链接 / 删除记录和文件 |
| 近 14 天柱状图 | 每天下载了多少条，一眼看出忙不忙 |
| 设置抽屉 | 画质上限、按作者分文件夹、退出抖音后是否自动重开、运行日志 |

# 常用命令

```bash
python douyin_dl.py                  # 正常监听收藏（默认带面板）
python douyin_dl.py --download-all   # 启动时把现有收藏全部补下回来
python douyin_dl.py --url <分享链接>  # 只下单个视频，不启动监听
python douyin_dl.py --check          # 只看登录状态
python douyin_dl.py --output D:\视频  # 指定下载目录
python douyin_dl.py --no-ui          # 不要面板
python douyin_dl.py --ui-port 9000   # 换面板端口
```

后台守护（崩了自动拉起，推荐日常使用）：

```bash
python douyin_dl/daemon.py
```

双击 `启动收藏下载.bat` 走的就是这条路：守护进程 + 主程序都在后台，面板自动弹出。
想彻底停掉：`taskkill /f /im pythonw.exe`。
连续 5 次启动即秒退时守护会放弃，避免无限重启。

# 画质

- 默认「最高画质」：在所有候选地址里按 **分辨率面积 → 码率 → 体积** 排序取第一
- 面板里可以设上限（1080P / 720P / 480P），适合省流量
- 下载支持 **Range 断点续传**（`.part` 临时文件），中断后重下会接着写
- 下完用 MP4 魔数（`ftyp`）或 ffprobe 校验，损坏的文件不会留下
- 图文作品按 `01.jpg / 02.jpg …` 存进同名文件夹

# 工作原理

```
你点「收藏」
   ↓
页面钩子(注入的 JS) 捕获 /aweme/v1/web/aweme/collect/ 请求
   ↓  请求体里 action=1 才是收藏，action=0 是取消
通过 Playwright expose_binding 直接回调 Python（零网络请求，绕开 CSP）
   ↓
无头 Chrome 带同一份 Cookie 打开详情页，抓一份「此刻有效」的播放地址
   ↓
按分辨率/码率选最优候选 → requests 多线程外下载 → 校验 → 落盘 → 通知面板
```

几个关键设计：

- **只认接口里的 `action=1`**，不依赖「点击坐标对得上号」这种脆弱判断（实测过：连点两个视频时点击记录会错位）
- **收藏列表只用来记录基线，永不触发下载** —— 列表第一页会自己轮换，拿它 diff 必然把历史收藏反复重下
- **每次下载都重新抓详情，不复用缓存** —— 播放地址签名很快过期，用旧地址会整片 403
- **候选地址全部失败时会逐个换**，不会因为第一条 403 就放弃
- 补全详情走**无头浏览器**，所以你眼前不会跳任何窗口或标签页

# 文件结构

```
douyin_dl.py            主程序入口 / 下载调度
douyin_dl/daemon.py     守护进程（崩了自动拉起）
douyin_dl/core.py       地址解析、选最高画质、下载、校验
douyin_dl/watcher.py    浏览器接管、页面钩子、收藏事件、无头补全
douyin_dl/ui.py         本地面板（HTTP + SSE，标准库实现）
douyin_dl/web/index.html 面板前端
tests/                  解析 / 监听逻辑 / 端到端测试
启动收藏下载.bat         Windows 双击启动

downloads/              下载的视频（_meta/ 里是每条视频的元数据）
.state.json             已下载记录（防重复）
.settings.json          面板里的设置
.chrome_profile/        浏览器登录态，别删
douyin_dl.log           运行日志
```

# 常见问题

**点了收藏没反应？**
看 `douyin_dl.log` 最后几行：

| 日志 | 含义 |
| --- | --- |
| 没有任何新行 | 钩子没认出按钮，或你点的不是这个 Chrome 窗口 |
| `检测到收藏点击` 但后面没有 `新收藏` | 请求没发出去 |
| `取消收藏 xxx (不下载)` | 这个视频本来就是已收藏的，点一下是取消 |
| `抓取最新视频信息` 后卡住或 `拿不到` | 详情接口没返回，会自动重试 |
| `所有候选地址都下载失败` | 该视频地址全部被拒（少见），日志里有完整 URL |

**提示「已经有一个下载进程在运行」**：程序是单实例的，会把已有窗口切到前台，直接刷就行。确实想重开就先关掉原来的窗口。

**双击后没有抖音窗口**：Chrome 被关掉后旧进程会自己退出并释放锁，重新双击即可。

**面板显示的还是旧样式**：浏览器缓存了旧页面，按 `Ctrl + F5` 强制刷新一次。

# 注意

- 监听期间**别关那个 Chrome 窗口**（可以最小化）
- 启动时会先记下你现有的收藏，**只下载这之后新收藏的视频**；想把历史收藏也补回来用 `--download-all`
- 取消收藏不会触发下载
- 仅供个人备份自己收藏的内容使用

# 更新记录

## v1.5

**新功能：自动翻页（设置里开关，默认开）**

- 推荐页不滑动就不会加载新视频，光等是不行的。「设置」→「自动翻页」开（默认就是开），
  打开后每隔几秒替你按一下方向键，滑到哪就下到哪，完全不用动手
- 间隔可调：「设置」→「自动翻页间隔」，1~60 秒，默认 3 秒
- 队列积压时自动减速：排队超过 12 个就先不滑了，等消化到安全线再继续，
  免得一口气塞几百个进去把队列堵死

**快了一个数量级**

- 抓视频详情不再每次重新开浏览器（原来每个视频要 30~45 秒），改成常驻一个无头
  浏览器反复用，单个详情 5 秒左右出结果，下载基本不再排队
- 详情页会把视频、图片、字体这些大流量资源直接掐掉，只要接口数据，
  省流量也更快（调试场景尤其明显）

**顺手改进**

- 下载目录可调：设置里「下载目录」输入框改成其他盘/文件夹，新视频就存那里
- 下载记录区可折叠

## v1.4

**新功能：自动下载推荐页视频（设置里开关，默认关）**

- 面板右上「设置」→「自动下载推荐页视频」→ 开。开着刷推荐页时，加载到的视频
  （推荐信息流 + 相关推荐）会自动进下载队列，不用一个个点收藏
- 「关」时和以前完全一样：只下载你收藏的
- 三个去重防线：同一会话不重复提交；已收藏的不重复下；已下载过的由下载器兜底跳过
- 开关即时生效，不用重启

## v1.3

这一版没加新功能，专门做体检：把整个项目逐行过了一遍，修掉 16 处会踩到的问题。
其中好几处是「平时看不出来，真遇上就束手无策」的那种。

**修好的坑**

- **返回顶部按钮点了没反应** —— 按钮里写的是 `scrollTo(...)`，在按钮自己的作用域里被解析成
  元素自己的滚动方法，而不是页面滚动。改成 `window.scrollTo` 并把逻辑收进 `goTop()`，
  另外加了 `T` 快捷键
- **校验失败的文件永远修不好** —— 下完之后发现不是有效视频，文件留在原地，
  再点重试就命中「已存在，跳过」，只能手动去文件夹里删。现在校验失败直接删掉
- **断点续传遇到 416 会卡死** —— 服务器说「你这段已经下完了」，老代码却当成失败，
  留下一个下载不掉的残片，这个视频从此再也下不下来。现在直接用已有的残片收尾
- **半截文件被当成成品** —— 网络中断时会得到一个大小不对的「完成」文件。加了长度校验，
  长度不够就继续下，不写成品
- **画质排序是反的** —— 「按画质」用的字符串比较，`720x1280` 排在了 `1080x1920` 前面。
  改成按分辨率面积比
- **图集作品永远挂在「排队中」** —— 图文作品下载完没发完成通知，面板上一直以为它还在排队
- **下载失败却一声不吭** —— 视频被删/私密/需要登录时抓不到详情，以前只是后台默默跳过，
  现在会带着原因出现在面板的失败列表里，点一下就重试
- **删除记录可能被「复活」** —— 面板直接改状态文件，和下载线程抢着写，删掉的记录会被写回来。
  改成由后台持锁统一删
- **面板断线时毫无提示** —— 所有按钮的请求都裸着发，后台一断就静默失败。现在统一走一个
  带容错的请求函数，断了会弹提示
- **未知大小时进度条永远是 0%** —— 服务器不给长度时看起来像卡死。现在直接显示「已下载 3.8 MB」
- **卡片墙每次推送都整体重建** —— 150 多张卡片每秒重建一遍，鼠标悬停会闪、图片会重新加载。
  加了内容指纹，没变化就不动 DOM
- **设置文件每秒被读 3 次** —— 合成一份状态要读三遍 `.settings.json`，现在只读一遍
- **控制台一直刷 favicon 404** —— 补了 204 响应
- **面板接口可以被路径穿越** —— `?id=../../etc/passwd` 这类 id 现在会被挡掉
- **卡片 onclick 里的 id 没转义** —— 加了白名单过滤
- **日志文件无限增长** —— 超过 5 MB 自动轮转一份

**顺手的改进**

- 打开设置抽屉立刻就能看到日志，不用等 3 秒轮询
- 重试成功后，失败列表里那条会自动消失

**测试**

- 新增 `tests/test_panel.py`：在临时目录造数据、起一个独立面板，用无头浏览器把搜索、
  筛选、排序、设置、快捷键、右键菜单、排队/进度/失败、重试、删除、接口健壮性等
  40 多项逐条跑一遍，不碰真实下载目录
